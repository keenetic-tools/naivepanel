# NaivePanel

Local web panel to manage a **NaiveProxy client** on a router running
**Entware** (Keenetic and other OpenWrt-like firmware). Flask backend + a single
HTML page — no CDN, no build step. MIT-licensed.

---

Локальная веб-панель управления **клиентом NaiveProxy** на роутере с **Entware**
(Keenetic и другие OpenWrt-подобные прошивки).

## Что это

- **Flask-приложение** (одна HTML-страница, без CDN / без build step).
- Сервер — **waitress** (прод, ограниченное число потоков); если не установлен —
  фолбэк на dev-сервер **Werkzeug** (`threaded=True`) с предупреждением в логе.
- Хранит **N пресетов** конфигурации клиента в `/opt/etc/naive/proxy/conf.d/<name>.json`.
- По activate копирует пресет в `/opt/etc/naive/proxy/config.json` (`chmod 0600`)
  и перезапускает `/opt/etc/init.d/S99naiveproxy`.
- Bind по умолчанию `127.0.0.1:8089`. Доступ из LAN — через внешний reverse proxy
  или напрямую (см. «Доступ из LAN без reverse proxy»).

## Возможности UI

- Карточка статуса: состояние, активный пресет, uptime, PID, версия панели.
- Поиск по пресетам (клавиша `/`), дублирование пресета в один клик (⧉ —
  пароль переносится, руками вводить не нужно).
- Экспорт/импорт всех пресетов JSON-файлом (бэкап/миграция между роутерами).
- Кнопка «пинг» в редакторе: TCP-доступность upstream с роутера (3с, без TLS).
- Светлая/тёмная тема: автоматически по системной, клик по ☀/☾ фиксирует выбор.
- Toast-уведомления, подсветка ERROR/WARNING в логе, горячие клавиши
  (Ctrl+S — сохранить, Esc — закрыть редактор).
- Доступный диалог подтверждения на `<dialog>` (фокус-ловушка браузера,
  Esc) вместо нативных `confirm()`.
- Просмотр лога: фильтр «только ошибки», скачивание и копирование в буфер
  (fallback через `execCommand` для прямого http-LAN, где Clipboard API
  недоступен вне secure context).
- Скелетон-заглушки при загрузке списка и live-подсветка некорректного
  upstream в форме редактора.
- Анти-перебор auth: >5 неудачных попыток ввода пароля с одного IP за 60с
  → 429 (анонимные запросы без `Authorization` не считаются).
- Визуальный полиш (v0.5.1): elevation-тени карточек, sticky-шапка
  с `backdrop-filter` (и фолбэком), пульсирующий индикатор «работает»,
  empty-states для пустого списка/поиска, `tabular-nums` для uptime/PID
  (цифры не «прыгают» при автообновлении), тонкий фоновый градиент.
  Всё в рамках прежних ограничений: один HTML-файл, без CDN, анимации
  только на `transform`/`opacity`, вес страницы +1.4 КБ к gzip.
- Обновление панели из UI: тихая проверка при загрузке страницы, бейдж
  «доступна vX.Y.Z», ченджлог релиза в диалоге, обновление одной кнопкой —
  с live-логом установщика, детектом перезапуска панели и автоперезагрузкой
  страницы. Прокси (naive) при этом не прерывается (см. «Обновление из UI»).
- E2E-проверка «Проверить прокси» (v0.12): настоящий запрос через listen
  активного пресета с ответом exit-IP — отличает «прокси не проксирует» от
  «недоступен upstream» (см. ниже). Спарклайн истории проверок монитора —
  в статус-карте (v0.13).
- Watchdog (v0.12): панель сама поднимает упавший naive; состояние и счётчик
  рестартов — в статус-карте (см. ниже).
- Автофейловер (v0.12): цепочка пресетов «основной → запасные» — после
  порога неудачных E2E-проверок панель переключает на следующий (см. ниже).
  Управление — в списке пресетов (v0.17): бейдж роли (`осн.`/`№N`), тумблер
  участия и режим «Порядок» с ↑↓; изменения применяются сразу.
  При нескольких запасных — на первого живого (проба вторым naive, v0.14).
- Авто-возврат на основной (v0.14, opt-in): TCP-гистерезис → проба живым
  naive → активация; неудачная проба — cooldown.
- Уведомления (v0.14): Telegram/webhook о переключениях, возвратах,
  рестартах watchdog'ом и исчерпании цепочки.
- Настройка Telegram из UI (v0.16): токен от @BotFather, chat_id и кнопка
  «Отправить тест» — без правки `panel.conf` и перезапуска панели.
- Смена пароля администратора из UI (v0.16): текущий пароль + новый, запись
  `admin.pass` атомарно — без SSH и `htpasswd`.
- Три колонки на широких экранах (v0.12): слева статус, пресеты и фейловер,
  в центре редактор с логом, справа — бинарник, панель, уведомления,
  обновления/откат. Средние экраны — две колонки, телефон — одна с тем же
  порядком «главное сверху».
- Обновление бинарника naive из UI (v0.11): автодетект openwrt-таргета,
  установка через install.sh, бейдж доступной версии (см. ниже).
- Откат версий из UI (v0.15): панель и бинарник возвращаются на сохранённый
  бэкап одной кнопкой — без SSH; список версий с размерами, чистка бэкапов
  (по одному или «оставить только последнюю»).

## API

| Метод | Путь | Что делает |
|-------|------|------------|
| `GET` | `/api/status` | `{active, current, init_present, init_script, pid, uptime, version, watchdog, failover}` |
| `GET` | `/api/configs` | список пресетов `{name, active, listen, proxy, username}`; `proxy` замаскирован (`https://user:***@host`), ответ `no-store` |
| `GET` | `/api/configs/<name>` | полный JSON-конфиг пресета |
| `POST` | `/api/configs` | создать пресет |
| `PUT` | `/api/configs/<name>` | обновить (если активный — propagate в `config.json` **и restart**; ответ содержит `restart:{rc,...}`) |
| `DELETE` | `/api/configs/<name>` | удалить (если не активный) |
| `POST` | `/api/configs/<name>/activate` | сделать активным + restart (конфиг **валидируется** — битый не роняет рабочий прокси) |
| `POST` | `/api/configs/<name>/duplicate` | копия пресета server-side, **включая пароль** |
| `GET` | `/api/configs/export` | все пресеты одним JSON-файлом (attachment; содержит пароли!); в файл всегда входит блок `failover` (необязателен только при импорте) |
| `POST` | `/api/configs/import` | импорт из файла export-формата; существующие не перезаписываются, битые отклоняются; блок `failover` применяется только к пустой цепочке и только если все имена есть — иначе `failover:{applied:false,reason}` |
| `POST` | `/api/probe` | TCP-доступность upstream с роутера (`{upstream}` → `{ms}` или `{error}`) |
| `POST` | `/api/e2e` | реальный запрос через listen активного пресета (или явный `{listen}`): туннель до echo-хоста + GET → `{ok, ms, exit_ip}` или `{ok:false, error}` |
| `GET` | `/api/e2e/history?last=120` | история периодических проверок монитора: `{entries:[{t,ok,ms}], stats:{availability, avg_ms, window_s}}` (спарклайн в статус-карте) |
| `GET`/`PUT`/`DELETE` | `/api/failover` | цепочка автофейловера: `PUT {"enabled":true,"chain":["home","backup"],"auto_return":true}` — имена валидируются, цепочка проверяется и при `enabled:false`, а без `chain` при `enabled:false` сохраняется текущая; `enabled` — строго JSON-булево (`"true"` → 400); `DELETE` остаётся для совместимости API; ответ — конфиг + состояние монитора (`monitor`, `chain_max`, `fails`, `switches`, `returns`, `return_watch`, `last_ok`, …) |
| `POST` | `/api/service/{start,stop,restart}` | управление через S99naiveproxy |
| `POST` | `/api/panel/restart` | перезапуск самой панели (после обновления файлов) |
| `GET` | `/api/update/check?force=1` | сверить версию с последним релизом GitHub (`{current, latest, available, notes, url}`; кэш 6ч, `force` обходит; сеть недоступна → 200 с `error`) |
| `POST` | `/api/update/apply` | запустить self-update: spawn отсоединённого `install.sh --yes --from-update --ref <тег>`; exit-код установщика пишется в лог; `202 {target,...}`, повторный запуск → `409` |
| `GET` | `/api/update/log?lines=60` | tail лога установщика + хвост лога панели (`panel`) + state обновления, `no-store` |
| `GET` | `/api/rollback` | что можно откатить: `{current, panel:[{version,size,ts}], binary:{present,tag,size}}` — версии панели в `backup/` + прошлый бинарник |
| `POST` | `/api/rollback` | откат: `{"panel":"vX.Y.Z"}` — восстановить файлы из бэкапа и перезапустить панель (текущая версия тоже уходит в бэкап, откат обратим); `{"binary":true}` — вернуть `naive.previous` и перезапустить прокси, если работал. Гейт как у update/apply |
| `DELETE` | `/api/rollback/<vX.Y.Z>` | удалить один бэкап панели |
| `POST` | `/api/rollback/cleanup` | `{"keep":N}` — удалить все бэкапы панели, кроме N новейших (по умолчанию 1) |
| `POST` | `/api/password` | смена пароля текущего Basic-пользователя: `{current,new}` → `{ok}`; `400` — неверный текущий или длина не 8–72 байта, `409` — auth выключен |
| `GET` | `/api/notify` | статус уведомлений: `{channel, enabled, telegram:{configured, chat_id, bot}, pending}`; токен не отдаётся |
| `POST`/`DELETE` | `/api/notify/telegram` | сохранить `{token, chat_id}` (пустой токен = не менять) или отключить; upsert в `panel.conf`, применяется сразу; `warning`, если ключ задан через env |
| `POST` | `/api/notify/test` | тестовое сообщение в Telegram (не чаще 1/5с): `200 {ok}`, `409` — канал не настроен, `429` — слишком часто, `502` — доставка не удалась |
| `GET` | `/api/logs?lines=100` | tail лог-файла: по умолчанию naive, `&src=panel` — лог самой панели (события безопасности, обновления, обрезки логов) |

## Локальный запуск (для разработки)

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install flask

# Пути по умолчанию под Entware; для Mac/Linux — подменить.
NAIVEPROXY_DIR=./etc/naiveproxy \
NAIVEPROXY_INIT=./etc/init.d/S99naiveproxy \
NAIVEPROXY_LOG=./var/log/naiveproxy.log \
NAIVEPANEL_BIND=127.0.0.1:8089 \
./.venv/bin/python naivepanel.py
```

Открыть `http://127.0.0.1:8089`.

Переменные окружения позволяют запускать панель где угодно без root —
главное, чтобы каталог пресетов существовал и был writable.

## Установка (install.sh)

Рекомендуемый способ — автоустановщик. Запускается **на роутере** (нужен
Entware с `opkg`). Скачивает файлы, закреплённые за тегом релиза, сверяет
контрольные суммы (`SHA256SUMS`), ставит init-скрипты и запускает панель:

```bash
curl -fsSL https://raw.githubusercontent.com/keenetic-tools/naivepanel/v0.17.1/install.sh | sh -s -- --with-auth
```

Запуск через пайп безопасен: подтверждение установки и ввод пароля читаются
с терминала (`/dev/tty`), а не из stdin скрипта. Для полностью неинтерактивного
режима добавьте `--yes`.

Флаги:

| Флаг | Что делает |
|------|------------|
| `--with-auth` | интерактивно создаёт `/opt/etc/naive/panel/admin.pass` (HTTP Basic) |
| `--bind HOST:PORT` | пишет `NAIVEPANEL_BIND` в `/opt/etc/naive/panel/panel.conf` |
| `--hosts LIST` | пишет `NAIVEPANEL_HOSTS` в `panel.conf` |
| `--ref TAG` | устанавливает конкретный тег (по умолчанию `v0.17.1`) |
| `--naive-target TGT` | openwrt-таргет бинарника naive, поверх авто-детекта |
| `--naive-ref TAG` | конкретный тег klzgrad/naiveproxy вместо последнего |
| `--naive-force` | переустановить бинарник naive, даже если он уже есть |
| `--skip-naive` | не трогать бинарник naive (только предупреждение) |
| `--no-naive-init` | не ставить `S99naiveproxy` (если свой init-скрипт уже есть) |
| `--yes` | неинтерактивный режим (без подтверждения) |
| `--uninstall` | остановить сервисы и удалить файлы |
| `--purge` | вместе с `--uninstall` — снести и конфиги (`admin.pass`, `conf.d`) |

Установщик идемпотентен: повторный запуск = обновление. Файлы панели
обновляются, а `admin.pass` и пресеты в `conf.d/` остаются нетронутыми.

Каталоги продукта (начиная с v0.2.0): `/opt/etc/naive/panel` — код панели и
`admin.pass`, `/opt/etc/naive/proxy` — пресеты (`conf.d/`), активный
`config.json` и `.active`. Установка поверх схемы < v0.2.0 мигрирует
автоматически: `/opt/naivepanel`, `/opt/etc/naivepanel`,
`/opt/etc/naiveproxy` переносятся в новое дерево, данные сохраняются.

Зависимости ставятся через `opkg`, а не pip: `python3` (если его ещё нет в
`/opt`), `python3-flask`, при `--with-auth` — `python3-bcrypt`. На фидах без
`python3-flask` (например `aarch64-k3.10`) установщик ставит `python3-pip`
и flask через `pip3`.

Бинарник `naive` установщик ставит сам, если его нет: определяет openwrt-таргет
по железу (`uname -m` + `/proc/cpuinfo`, энддиан MIPS — по ELF-заголовку),
скачивает подходящий prebuilt с [klzgrad/naiveproxy][np] (приоритет — `-static`
сборки) и проверяет его запуском `--version` до установки. Существующий
бинарник не трогается — обновляется отдельно, кнопкой из панели (ниже).
Не удалось (экзотическое железо, нет хода в GitHub) — установка панели
продолжается, выводится подсказка для ручной установки.

Пример с LAN-доступом:

```bash
curl -fsSL https://raw.githubusercontent.com/keenetic-tools/naivepanel/v0.17.1/install.sh \
  | sh -s -- --with-auth --bind 192.168.1.1:8089 --hosts '192.168.1.1:8089,router.local:8089'
```

### Обновление из UI

Панель умеет обновлять себя сама — без SSH. В секции «Панель» при загрузке
страницы тихо сверяется версия с GitHub (кэш 6ч); если есть свежий релиз,
появляется бейдж «доступна vX.Y.Z», кнопки «Обновить» и «Что нового»
(ченджлог релиза в диалоге). Кнопка «Обновить»:

1. подтверждение — панель перезапустится на несколько секунд, прокси
   (naive) продолжит работать без прерывания;
2. панель скачивает `install.sh` свежего тега и отсоединённо запускает
   `install.sh --yes --ref vX.Y.Z` — тот же путь, что и ручной апгрейд:
   сверка `SHA256SUMS`, зависимости через `opkg`, идемпотентность;
3. UI показывает live-лог установщика, детектит перезапуск панели
   (падение/подъём `api/status` + смена версии) и перезагружает страницу.

Детали и страховки:

- Установщик в конце сам делает `S99naivepanel restart` — процесс панели
  умирает посреди обновления, поэтому spawn идёт в новой сессии (как у
  `/api/panel/restart`), а финальный «успех» UI определяет по версии.
- Перед запуском старые файлы копируются в `/opt/etc/naive/panel/backup/v<старой>/`
  (`naivepanel.py`, `index.html`, init-скрипты) — оттуда же работает кнопка
  «Откат версий…» (см. ниже); вручную по SSH их тоже можно вернуть.
- Повторный `apply` при живом установщике → `409`. Умерший установщик
  распознаётся по pid в `update.state` (state → `failed`, retry сразу);
  записи без pid (версии до v0.8.1) протухают через 15 минут.
- `apply` разрешён только с паролем (`--with-auth`) либо при loopback-bind:
  обновление меняет код панели, отдавать его в LAN без auth нельзя.
- GitHub недоступен с роутера (типично для этих сетей) — `check` отвечает
  200 с `error`, UI показывает тихую строку «не удалось проверить».
- Репозиторий и базовые URL переопределяются env: `NAIVEPANEL_REPO`,
  `NAIVEPANEL_UPDATE_API`, `NAIVEPANEL_UPDATE_RAW` (зеркала и тесты);
  `install.sh` тоже читает `NAIVEPANEL_REPO`. Лог установщика —
  `/opt/var/log/naivepanel-update.log` (`NAIVEPANEL_UPDATE_LOG`).

### Обновление бинарника naive из UI

В секции «Бинарник naive» панель показывает установленную версию, таргет
сборки и доступный релиз [klzgrad/naiveproxy][np] (тихий авто-check при
загрузке, кэш 6ч). Кнопка «Обновить» (или «Установить», если бинарника нет):

1. подтверждение — прокси перезапустится, соединения оборвутся на секунду;
   сама панель продолжает работать;
2. фоновый поток панели скачивает asset под сохранённый таргет (приоритет —
   `-static` сборки), распаковывает и **проверяет запуском `--version`**;
3. только после проверки бинарник заменяется (rename — работающий naive
   доживает на старом образе), прежний остаётся
   `/opt/etc/naive/proxy/backup/naive.previous` (+ его тег в
   `naive.previous.tag`, пишется с v0.15), и перезапускается
   `S99naiveproxy`, если он работал.

Тег и таргет последней установки хранятся маркерами `naive-version` /
`naive-build` в `/opt/etc/naive/proxy/` (их пишет и `install.sh`): по точному
тегу считается «есть ли обновление» — вывод `naive --version` теряет суффикс
пересборки `-N`. Бинарник, поставленный вручную, работает тоже: маркеров нет —
версия спрашивается у самого бинарника.

Детали и страховки:

- Сбой скачивания/распаковки/проверки **не трогает рабочий бинарник** —
  состояние с ошибкой видно в диалоге обновления, retry доступен сразу.
  Гейт доступа тот же, что у обновления панели: пароль либо loopback-bind.
- Источник переопределяется: `NAIVEPROXY_SRC_REPO`, `NAIVEPROXY_SRC_API`,
  `NAIVEPROXY_BIN` (env или panel.conf); лог —
  `/opt/var/log/naivepanel-naive.log` (`NAIVEPROXY_UPDATE_LOG`), он же
  попадает в ежечасную обрезку логов.

### Откат версий (v0.15)

Обновления панели и бинарника давно сохраняют заменяемое (см. секции выше),
но достать бэкап можно было только по SSH. Кнопка «Откат версий…» в секции
«Панель» закрывает ровно случай «роутер без консоли под рукой»:

- **Панель** — список версий из `backup/vX.Y.Z/` (новые сверху, с размерами).
  Откат восстанавливает `naivepanel.py`, `index.html` и оба init-скрипта,
  затем перезапускает саму панель — UI ждёт подъёма и перезагружает страницу,
  как при обновлении. Перед откатом текущие файлы тоже уходят в бэкап:
  откат обратим в обе стороны («обновился — не понравилось — вернул —
  передумал — вернул обратно»). Конфиги (`panel.conf`, `conf.d`,
  `failover.json`, `admin.pass`) не трогаются никогда.
- **Бинарник** — один шаг назад на `naive.previous`: перед возвратом бэкап
  проверяется запуском `--version` (битый не ставится), тег восстанавливается
  из `naive.previous.tag`, `S99naiveproxy` перезапускается, если прокси
  работал. Бэкапы старше v0.15 тега не имеют — UI честно покажет
  «версия неизвестна».
- **Чистка** — бэкапы панель копит и не удаляет сама (это ~200 КБ на версию):
  ✕ у строки удаляет одну версию, «Оставить только последнюю» — все, кроме
  самой свежей. Строка «откат: бэкапов N (X МБ)» под кнопкой показывает,
  сколько уже накопилось.

Гейт доступа — как у обновлений: пароль (`--with-auth`) либо loopback-bind;
откат панели и бинарника меняет код, отдавать это в LAN без auth нельзя.
Откат при живом обновлении → `409`, откат на текущую версию → `400`.

### Настройки панели (panel.conf)

Все настройки панели живут в **`/opt/etc/naive/panel/panel.conf`** — этот файл
читает сам `naivepanel.py`, поэтому настройки переживают любые обновления
(установщик перезаписывает init-скрипт при каждом апгрейде, так что вписывать
настройки туда нельзя). Файл создаётся установщиком один раз как шаблон;
**существующий файл никогда не перезаписывается** — правки руками сохраняются.

```ini
# KEY="VALUE"; комментарии — только с начала строки
NAIVEPANEL_BIND="192.168.1.1:8089"
NAIVEPANEL_HOSTS="192.168.1.1:8089,router.local:8089"
#NAIVEPANEL_PASS="/opt/etc/naive/panel/admin.pass"
#NAIVEPROXY_DIR="/opt/etc/naive/proxy"
#NAIVEPROXY_INIT="/opt/etc/init.d/S99naiveproxy"
#NAIVEPROXY_LOG="/opt/var/log/naiveproxy.log"
#NAIVEPROXY_PID="/opt/var/run/naiveproxy.pid"
# Бинарник naive и источник его обновлений (зеркала и тесты)
#NAIVEPROXY_BIN="/opt/bin/naive"
#NAIVEPROXY_SRC_REPO="klzgrad/naiveproxy"
#NAIVEPROXY_SRC_API="https://api.github.com"
#NAIVEPANEL_THREADS="4"
# Логи: фоновый поток панели раз в час обрезает файлы больше NAIVEPANEL_LOG_MAX
# до последних NAIVEPANEL_LOG_KEEP байт (0 в NAIVEPANEL_LOG_MAX отключает обрезку)
#NAIVEPANEL_LOG="/opt/var/log/naivepanel.log"
#NAIVEPANEL_LOG_MAX="5242880"
#NAIVEPANEL_LOG_KEEP="524288"
# Watchdog: фоновый поток панели поднимает упавший naive (0 — выключить)
#NAIVEPANEL_WATCHDOG="1"
#NAIVEPANEL_WATCHDOG_INTERVAL="15"
# E2E-проверка «Проверить прокси»: echo-хост, через который меряется exit-IP
# (можно указать свой; http:// тоже поддержан)
#NAIVEPANEL_E2E_URL="https://api.ipify.org/"
# Автофейловер: двухскоростной монитор (цепочка пресетов — в UI, хранится
# в /opt/etc/naive/proxy/failover.json). Здоров — проверка раз в INTERVAL;
# первая неудача — частые проверки раз в FAST до порога/восстановления.
# 0 в NAIVEPANEL_FAILOVER отключает монитор целиком — и переключения,
# и историю проверок
#NAIVEPANEL_FAILOVER="1"
#NAIVEPANEL_FAILOVER_INTERVAL="30"
#NAIVEPANEL_FAILOVER_FAST="5"
#NAIVEPANEL_FAILOVER_THRESHOLD="3"
# Авто-возврат на основной (включается чекбоксом в UI): N TCP-живых подряд
# у кандидата → проба живым naive → E2E → активация; неудачная проба → cooldown
#NAIVEPANEL_FAILOVER_RETURN_ALIVE="3"
#NAIVEPANEL_FAILOVER_RETURN_COOLDOWN="900"
# История E2E-проверок для спарклайна (кольцевой буфер, переживающий рестарт)
#NAIVEPANEL_E2E_HISTORY="/opt/etc/naive/proxy/e2e-history.jsonl"
#NAIVEPANEL_E2E_KEEP="2880"
# Уведомления (Telegram или webhook): панель докладывает о переключениях,
# возвратах, рестартах watchdog'ом и исчерпании цепочки. Секреты — только здесь
#NAIVEPANEL_TG_TOKEN=""
#NAIVEPANEL_TG_CHAT=""
#NAIVEPANEL_NOTIFY_URL=""
```

Приоритет: **env > panel.conf > встроенный дефолт** — переменные окружения
удобны для dev-запуска, файл — для роутера. Ключи вне списка из шаблона
игнорируются (опечатка не применится молча — в лог уйдёт warning). После
правок: `/opt/etc/init.d/S99naivepanel restart`.

Флаги `--bind`/`--hosts` обновляют соответствующие ключи внутри существующего
файла. Историческая схема с `/opt/etc/init.d/rc.conf` не работала (файл никто
не читал) — установщик, начиная с v0.4.1, переносит найденные там
`NAIVEPANEL_BIND/HOSTS` в `panel.conf`.

### Ротация логов

Логи аппендятся без ограничений всё время, пока сервисы работают, а раздел
entware на роутере маленький — разросшийся `/opt/var/log/naiveproxy.log`
умеет заполнить его целиком (после чего ни naive, ни панель не стартуют).
Поэтому панель фоновым потоком раз в час проверяет все известные логи:
`naiveproxy.log`, `naivepanel.log`, `naivepanel-update.log`,
`naivepanel-naive.log` и log-файл из ключа `log` активного пресета. Файлы больше `NAIVEPANEL_LOG_MAX` (по умолчанию
5 МБ, как в init-скриптах) обрезаются до последних `NAIVEPANEL_LOG_KEEP` байт
(512 КБ). Инод файла сохраняется — работающий naive продолжает писать в тот же
файл, место освобождается сразу. Init-скрипты дополнительно обнуляют слишком
большой лог при старте: страховка на случай, если панель остановлена, а прокси
работает. `NAIVEPANEL_LOG_MAX=0` отключает обрезку.

### Watchdog (авто-рестарт naive)

Init-скрипты Entware не supervise'ят процессы: если naive упал (OOM, баг), он
лежит до ручного вмешательства. Поэтому панель фоновым потоком (как
ротация логов) следит за прокси и поднимает его сама. Семантика консервативная:

- рестарт только по **наблюдаемому переходу** «работал → упал»: после старта
  панели «прокси не работает» — не сигнал (неизвестно, остановили ли его
  руками до нас; автозапуск после ребута — задача init-скрипта);
- **штатный stop не трогаем**: `S99naiveproxy stop` пишет маркер
  `/opt/etc/naive/proxy/.stopped`, `start` снимает — пока маркер на месте,
  watchdog молчит (работает и для stop через SSH);
- пауза ~3с до рестарта закрывает гонку с `restart` (между stop и start
  сервис пару секунд «лежит» штатно);
- **флаппинг гасим**: 3 рестарта за 10 минут — watchdog отключается до
  перезапуска панели (ошибка в логе панели); так падающий в loop бинарник
  не занимает роутер бесконечными рестартами;
- состояние видно в статус-карте (`watchdog: вкл · ↻N`) и в `GET /api/status`.

Если панель сама остановлена, watchdog не работает — это ограничение подхода
(крон-фолбэк в [ROADMAP](docs/ROADMAP.md)). Отключение:
`NAIVEPANEL_WATCHDOG="0"` в panel.conf.

### E2E-проверка «Проверить прокси»

Кнопка в секции «Сервис» прогоняет **настоящий клиентский запрос через
listen-порт активного пресета**: HTTP CONNECT (для `http://`-listen) или
SOCKS5-туннель до echo-хоста, затем GET за exit-IP (по умолчанию
`https://api.ipify.org/`, меняется через `NAIVEPANEL_E2E_URL`). Это сильнее
TCP-пинга upstream в редакторе: проверяется вся цепочка — listen жив,
креды к upstream приняты, форвардинг работает, DNS резолвится на стороне
прокси. **Успех — только полный ответ echo-хоста**: naive подтверждает
туннель, не дожидаясь коннекта к upstream, поэтому «ACK, а затем обрыв
данных» (типично для лежащего upstream-сервера) считается неудачей с
причиной в ответе.

### История E2E-проверок и спарклайн

Та же E2E-проверка выполняется **фоновым монитор-потоком** раз в
`NAIVEPANEL_FAILOVER_INTERVAL` секунд (30; при сбое чаще — см. фейловер
ниже) — не только при включённом фейловере: пока есть активный пресет и
прокси не остановлен штатно, каждая проверка пишется в кольцевой буфер
`e2e-history.jsonl` (последние `NAIVEPANEL_E2E_KEEP` записей, по умолчанию
сутки при 30-секундном ритме — ≈90 КБ; файл переживает рестарт панели).
Статус-карта рисует из буфера спарклайн-полоску (зелёный/красный по
проверкам) с доступностью и средней задержкой за окно.
`GET /api/e2e/history?last=120` отдаёт записи и статистику; монитор
выключается только `NAIVEPANEL_FAILOVER=0`.

### Автофейловер пресетов

Цепочка «основной → запасные» живёт в карточке «Пресеты», отдельной карточки
нет (хранится в `/opt/etc/naive/proxy/failover.json`). В строке пресета —
бейдж роли (`осн.`/`№N`) и тумблер `⛓` участия; режим «Порядок» показывает
участников по приоритету с ↑↓, остальные — по алфавиту. Каждое изменение
сразу пишется в `failover.json`; удаление активного из цепочки — с
подтверждением; новый или дублированный пресет в цепочку не попадает;
удаление пресета убирает его из цепочки; пустая цепочка выключает
фейловер.

Монитор — **двухскоростной**: пока
прокси здоров, E2E-проверка активного пресета раз в
`NAIVEPANEL_FAILOVER_INTERVAL` секунд (30); первая неудача переводит в
режим частых проверок раз в `NAIVEPANEL_FAILOVER_FAST` секунд (5) —
порог `NAIVEPANEL_FAILOVER_THRESHOLD` неудач подряд (3) добивается за
секунды, и панель переключает на следующий пресет цепочки тем же кодом,
что и ручной activate (валидация конфига + рестарт сервиса). Итого
переключение через ~20–40 секунд после сбоя; восстановление возвращает
редкий ритм. Семантика:

- **только вперёд по умолчанию**: назад, на основной, панель не возвращается
  сама — авто-возврат стал бы источником флаппинга. Опционально включите
  чекбокс «возвращать на основной» (см. ниже) — с двойной проверкой;
- при нескольких запасных каскад переключает на **первого живого**, а не
  первого существующего: кандидат проверяется «пробой» — временным naive из
  CLI (`--listen socks://127.0.0.1:<порт> --proxy <URI>`) с полным E2E
  через него, без активации и рестарта сервиса. Единственный запасной
  активируется сразу — скорость важнее, E2E проверит следующим тиком;
- гистерезис: одна осечка — не повод переключать; неудача — всё, кроме
  полного ответа echo-хоста (включая «туннель подтверждён, но данные не
  пошли»). От разовых сбоев самого echo-хоста защищает порог; для
  надёжности укажите свой `NAIVEPANEL_E2E_URL`;
- монитор активен, только пока активен пресет из цепочки: активировали
  что-то другое — панель не вмешивается; штатный stop (маркер) — тоже;
- цепочка исчерпана (запасных больше нет) — ERROR в лог панели, проверка
  продолжается; переключения пишутся в лог и видны в UI («переключений: N»,
  во время частых проверок — пометка «частые проверки»).

`NAIVEPANEL_FAILOVER="0"` отключает монитор целиком.

### Авто-возврат на основной (opt-in)

Чекбокс «возвращать на основной» — в карточке «Пресеты».
Работает только при стабильном текущем пресете (последняя проверка ok):

1. каждый цикл монитор **TCP-пингует** upstream всех пресетов цепочки
   раньше текущего (дёшево, без активации);
2. кандидат набрал `NAIVEPANEL_FAILOVER_RETURN_ALIVE` (3) живых подряд —
   поднимается **проба**: второй naive на свободном localhost-порту с
   CLI-флагами пресета-кандидата, через него гоняется полный E2E;
3. проба прошла — кандидат активируется; регулярная проверка нового
   активного подтвердит, а если нет — фейловер уведёт вперёд как обычно;
4. TCP жив, а E2E нет (креды/тёртый TLS) — кандидату cooldown
   `NAIVEPANEL_FAILOVER_RETURN_COOLDOWN` (900с), повтор позже.

Статус в UI показывает прогресс («ждём возврата: gw1 2/3», «возвратов: N»).
Ручной возврат кнопкой «→» работает всегда и мигом.

### Уведомления (Telegram / webhook)

Панель докладывает о своих автоматических решениях: переключение фейловера,
авто-возврат (и отложенный — проба не прошла), рестарт naive watchdog'ом,
отключение watchdog'а по флаппингу, исчерпание цепочки.

**Каналы** (panel.conf, секреты только там — UI показывает статус канала
и счётчик отложенных, Telegram настраивается ниже):

- **Telegram**: `NAIVEPANEL_TG_TOKEN` (бот от @BotFather) +
  `NAIVEPANEL_TG_CHAT`. chat_id — ваш личный числовой id (@userinfobot) —
  бот пришлёт **личные сообщения** (сначала напишите боту `/start`: Telegram
  запрещает ботам писать первыми); или id группы `-100…`, или @username
  канала;
- **webhook**: `NAIVEPANEL_NOTIFY_URL` — POST JSON `{event, text, ts}`.

Настроить Telegram можно из UI: «Обслуживание → Уведомления» — токен от
@BotFather, chat_id и кнопка «Отправить тест». Токен хранится только в
`panel.conf` и никогда не возвращается в браузер; после сохранения канал
включается сразу, без перезапуска панели. Webhook по-прежнему задаётся
только в `panel.conf`; при наличии обоих каналов приоритет у Telegram.

**Доставка — три слоя** (важно за блокировками: Telegram напрямую с
роутера недоступен):

1. **через активный naive** (`curl -x socks5h://…`): DNS тоже через прокси.
   В момент большинства событий какой-то прокси уже работает —
   «переключились на backup» отправится через новый активный, «авто-возврат»
   — через оживший основной;
2. **напрямую**: webhook на своём сервере и незаблокированные каналы.
   Практичный вариант для самых критичных событий — крошечный relay на
   своём зарубежном сервере (даже просто location в caddy), пересылающий
   POST в Telegram: обычный HTTPS до своего сервера не блокируется;
3. **если недоступно всё**: событие копится в `notify-pending.jsonl`
   (до 50, переживает рестарт панели) и доставляется **первым ожившим
   путём** — watchdog/failover поднимут прокси, sender увидит. Доклад с
   опозданием лучше потерянного.

Дедуп 1/мин на тип события; ошибки доставки — warning в лог панели,
монитор не роняют.

### Установка бинарника naive

### Установка бинарника naive

Первичную установку делает `install.sh` сам: определяет openwrt-таргет по
железу и скачивает prebuilt-сборку с [klzgrad/naiveproxy releases][np]
(приоритет — `-static`, musl, без зависимостей от библиотек в `/opt/lib`),
проверяет её запуском `--version` и кладёт в `/opt/bin/naive` — путь, которого
ждёт `S99naiveproxy`. Обновляется бинарник кнопкой из панели (см. выше
«Обновление бинарника naive из UI»).

Таблица детекта (по `uname -m` + `/proc/cpuinfo`):

| uname -m | уточнение | таргет |
|---|---|---|
| `aarch64` | `CPU part`: `0xd03`/`0xd08`/`0xd0e` → a53/a72/a76, прочее → generic | `aarch64_cortex-a53` … `aarch64_generic` |
| `armv7l` | `CPU part` + `Features` (neon/vfpv4 → суффиксы) | `arm_cortex-a7[_neon-vfpv4|_vfpv4]`, `arm_cortex-a9[_neon]` и др. |
| `armv6l` / `armv5l` | — | `arm_arm1176jzf-s_vfp` / `arm_arm926ej-s` |
| `mips` | энддиан по ELF-заголовку `/bin/sh`; `cpu model` 24Kc/1004Kc → 24kc | `mipsel_24kc`, `mipsel_mips32` (big-endian — сборок нет) |
| `x86_64` / `i686` | — | `x86_64` / `x86` |

Авто-детект промахнулся или хочется конкретную версию — флаги:

```bash
install.sh --yes --naive-target aarch64_cortex-a53   # поверх детекта
install.sh --yes --naive-ref v150.0.7871.63-1        # конкретный тег
install.sh --yes --naive-force                       # переустановить имеющийся
```

Ручная установка (например, сеть без хода в GitHub) — как раньше:

```bash
tar -xJf naiveproxy-v*-openwrt-*.tar.xz
cp naiveproxy-v*/naive /opt/bin/naive && chmod +x /opt/bin/naive
```

Если бинарник уже лежит в другом месте — достаточно symlink:

```bash
ln -sf /opt/naiveproxy/bin/naiveproxy /opt/bin/naive
```

## Ручной деплой на Keenetic (Entware)

> Требуется установленный пакет `naive-proxy` в Entware и, опционально,
> `python3` (если Python < 3.10 — ставим пакет `python3`). На Keenetic
> python3 в Entware уже есть.

```bash
# 1. Копируем файлы (через sshfs, scp или WebUI Keenetic)
ssh root@router
mkdir -p /opt/etc/naive/panel/templates
mkdir -p /opt/etc/naive/proxy/conf.d

# Положить naivepanel.py + templates/index.html (нужен для render_template)
scp naivepanel.py root@router:/opt/etc/naive/panel/
scp -r templates  root@router:/opt/etc/naive/panel/
scp S99naivepanel   root@router:/opt/etc/init.d/
scp S99naiveproxy   root@router:/opt/etc/init.d/    # если у тебя ещё нет
ssh root@router "chmod +x /opt/etc/init.d/S99naiveproxy /opt/etc/init.d/S99naivepanel"

# 2. (опционально) HTTP Basic auth
#    Панель слушает 127.0.0.1 — опасно без auth, если кто-то может
#    подключиться по SSH на роутер. Требуется пакет python3-bcrypt в Entware.
opkg update && opkg install python3-bcrypt
#    htpasswd в Entware отсутствует — генерируем bcrypt-хэш через python3
#    (пароль вводится скрыто). Формат строки: admin:$2b$…
python3 -c 'import bcrypt,getpass; print("admin:"+bcrypt.hashpw(getpass.getpass().encode(),bcrypt.gensalt()).decode())' \
  > /opt/etc/naive/panel/admin.pass
chmod 0600 /opt/etc/naive/panel/admin.pass

# 3. Запуск
/opt/etc/init.d/S99naivepanel start
/opt/etc/init.d/S99naivepanel status

# 4. (опционально) Автозапуск после перезагрузки
#    В WebUI Keenetic → Управление → Автозапуск → /opt/etc/init.d/S99naivepanel
#    или вручную:
ln -sf /opt/etc/init.d/S99naivepanel /opt/etc/rc.d/S99naivepanel
```

Панель будет доступна на `http://127.0.0.1:8089` (только с роутера).

### Смена пароля из UI

«Обслуживание → Панель → Сменить пароль…» — текущий пароль, новый (8–72 байта)
и повтор. Меняется только запись текущего пользователя в `admin.pass`, файл
пишется атомарно; после смены браузер переспросит креды. Доступно только при
включённой auth (`admin.pass` существует).

### Доступ из LAN

Через существующий **Caddy** на роутере или **Xkeen-UI reverse proxy**:

```caddyfile
naivepanel.local.lan {
    basicauth {
        admin $2a$14$...
    }
    reverse_proxy 127.0.0.1:8089
}
```

Панель за reverse proxy видит чужой `Host` (`naivepanel.local.lan`) — добавь
его в allowlist, иначе 403 (см. «Безопасность»):

```ini
# в /opt/etc/naive/panel/panel.conf
NAIVEPANEL_HOSTS="naivepanel.local.lan"
```

Или просто SSH-туннель: `ssh -L 8089:127.0.0.1:8089 root@router`.

### Доступ из LAN без reverse proxy

Прокси не обязателен, если закрыты три вещи: auth, Host-allowlist и
доступность порта. Минимальный безопасный вариант:

```bash
# 1. Basic auth обязателен — без него LAN-bind = открытые пароли upstream-прокси
opkg update && opkg install python3-bcrypt
#    htpasswd в Entware отсутствует — генерируем bcrypt-хэш через python3
python3 -c 'import bcrypt,getpass; print("admin:"+bcrypt.hashpw(getpass.getpass().encode(),bcrypt.gensalt()).decode())' \
  > /opt/etc/naive/panel/admin.pass
chmod 0600 /opt/etc/naive/panel/admin.pass

# 2. Bind на LAN-адрес (НЕ 0.0.0.0 — иначе торчим и в WAN/VPN/guest-сегменты)
#    и allowlist Host-заголовков (анти-DNS-rebinding) — в /opt/etc/naive/panel/panel.conf.
#    Без NAIVEPANEL_HOSTS разрешены только адрес bind и loopback-алиасы —
#    доступ по имени роутера (router.lan и т.п.) потребует явного allowlist.
NAIVEPANEL_BIND="192.168.1.1:8089"
NAIVEPANEL_HOSTS="192.168.1.1:8089,router.local:8089"

# 3. Файрвол Keenetic: порт 8089 только с твоих устройств; guest-сегмент — закрыт.
```

Остаточный риск — открытый HTTP: пароль Basic auth можно перехватить активным
MITM в LAN (ARP-spoofing, скомпрометированное устройство). Для доверенной
домашней сети это обычно приемлемо; если в сегменте есть недоверенные
устройства — поднимай TLS через Caddy или ходи по SSH-туннелю.

Неудачные попытки auth (401) и отклонённые Host (403) пишутся в
`/opt/var/log/naivepanel.log`.

## Поля конфига

NaivePanel собирает минимальный JSON, совместимый с бинарником `naive` из
[klzgrad/naiveproxy](https://github.com/klzgrad/naiveproxy):

```json
{
  "listen": "socks://127.0.0.1:1080",
  "proxy": "https://user:pass@host"
}
```

Поле `listen` поддерживает несколько адресов — тогда это массив. В UI их вводят
по одному на строку (или через запятую); один адрес сохраняется как строка
(компактнее), несколько — как массив:

```json
{
  "listen": ["socks://127.0.0.1:1080", "http://127.0.0.1:8080"],
  "proxy": "https://user:pass@host"
}
```

Дополнительные поля (опционально, через раздел «Дополнительно» в UI):

| Поле в UI | Ключ в JSON | Назначение |
|-----------|-------------|------------|
| log | `log` | путь к лог-файлу |
| host-resolver-rules | `host-resolver-rules` | `MAP proxy.example.com 1.2.3.4` |
| extra-headers | `extra-headers` | дополнительные HTTP-заголовки (через `\r\n`) |
| insecure-concurrency | `insecure-concurrency` | 1..4 (см. USAGE.txt — снижает детектируемость) |

## Безопасность

- Bind по умолчанию только `127.0.0.1`; LAN-bind — по чеклисту
  «Доступ из LAN без reverse proxy».
- `config.json`, `.active`, `*.json` в `conf.d/` — `chmod 0600`.
- Если есть `/opt/etc/naive/panel/admin.pass` — **каждый** запрос требует HTTP Basic
  auth (bcrypt, формат htpasswd `user:$2y$…`). Без пакета `python3-bcrypt` в
  Entware auth fail-closed (401 на любой запрос + ошибка в лог).
- Успешная Basic-проверка кэшируется на 5 минут (сбрасывается сразу при
  изменении `admin.pass`) — поллинг UI каждые 3с не гоняет bcrypt постоянно.
- **Host-allowlist включён всегда** (с v0.4.0). Если задан `NAIVEPANEL_HOSTS`
  (список через запятую, точные строки Host с портом) — пропускаются только
  они. Если не задан — адрес bind + loopback-алиасы (`127.0.0.1[:8089]`,
  `localhost[:8089]`, IPv6-формы). Прочие Host — 403: чужое имя хоста —
  маркер DNS-rebinding. Поэтому reverse proxy со своим именем требует явного
  `NAIVEPANEL_HOSTS`.
- Активация пресета валидирует имя: `^[a-zA-Z0-9_\-.]{1,64}$` (нет path-traversal).
- **Схема конфига валидируется** перед activate/PUT/импортом: непустые
  `listen`/`proxy`, URI со схемой, диапазон `insecure-concurrency` 1..4 — битый
  (например, руками отредактированный) пресет не перезапишет рабочий `config.json`.
  Схема `proxy` ограничена `https://` / `http://` / `quic://` — `file://` и
  прочие схемы отклоняются на activate/PUT/импорте.
- **Security-заголовки** на каждом ответе: `Content-Security-Policy`
  (`default-src 'none'`, скрипты только по одноразовому nonce
  `script-src 'nonce-…'` — инъекция `<script>` без nonce не выполнится,
  внешние origin'ы запрещены, `connect-src 'self'` против эксфильтрации;
  `style-src 'unsafe-inline'` — inline-стили и `style=""` шаблона),
  `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
  `Referrer-Policy: no-referrer`.
- Bind на `0.0.0.0` — warning в лог: на роутере это ещё и WAN/VPN/guest-сегменты.
- 401 (auth failed) и 403 (host rejected) пишутся в лог панели.
- Мутирующие запросы (POST/PUT/DELETE) требуют заголовок `X-Requested-With`
  (ставит UI) — защита от CSRF: Basic-креды браузер прикладывает к кросс-сайтовым
  запросам автоматически, поэтому одной auth тут недостаточно.
- Анти-перебор: >5 неудачных auth **с предъявленными кредами** с одного IP за
  60с → 429 (без блокирующего сна, чтобы флуд не занимал рабочие потоки).
  Анонимные пробы без заголовка `Authorization` не считаются. За reverse-proxy
  все клиенты делят один `remote_addr`, поэтому счётчик общий: ошибки ввода
  пароля одним клиентом дают 429 всем.
- `/api/configs/export` и `/api/logs` отдаются с `Cache-Control: no-store` —
  ответы с секретами не оседают в кеше браузера и промежуточных прокси;
  список `GET /api/configs` тоже `no-store` и маскирует пароли
  (`https://user:***@host`).
- Пароли upstream через API не возвращаются: `GET /api/configs/<name>` отдаёт
  upstream/username разобранными, но без пароля; пустое поле пароля в форме
  при сохранении означает «оставить прежний». Креденшалы в proxy-URI
  percent-encode'ятся (`@ : /` и т.п. в пароле не ломают URI).
- **Исключение — export**: `GET /api/configs/export` сознательно содержит
  proxy-URI с паролями — бэкап без кредов не был бы бэкапом. Файл уходит как
  `Content-Disposition: attachment` по явному клику «Экспорт»; импорт
  (`/api/configs/import`) существующие пресеты не перезаписывает и валидирует
  каждый. Не хранить экспорт-файл в общедоступных местах.
- `/api/logs` маскирует креды в URI (`scheme://user:pass@host` →
  `scheme://user:***@host`) и читает лог с конца файла, а не целиком.
- PUT активного пресета применяет изменения сразу (перезаписывает
  `config.json` и рестартует сервис, как activate); ответ содержит результат
  рестарта, UI показывает сбой, если он случился.
- Размер тела запроса ограничен 256 КБ (`MAX_CONTENT_LENGTH`).
- Пароль панели и `admin.pass` НЕ коммитить в git.

## Разработка

Перед PR-ом (то же, что гоняет CI):

```bash
./.venv/bin/python -c "import ast; ast.parse(open('naivepanel.py').read())"  # syntax
sh -n S99naiveproxy && sh -n S99naivepanel                                    # shell syntax
./.venv/bin/python -m pytest -q                                              # API-тесты, без сети
./.venv/bin/ruff check naivepanel.py tests/                                  # линт
./.venv/bin/bandit -q -ll -r naivepanel.py                                   # security-скан
```

E2E на настоящем Entware (нужен Docker):

```bash
./docker-e2e.sh              # установка + API-проверки (--yes)
./docker-e2e.sh --with-auth  # интерактивно: Basic auth
```

Скрипт поднимает локальный HTTPS-сервер, имитирующий
`raw.githubusercontent.com`, и прогоняет `install.sh` в контейнере с Entware:
сверка контрольных сумм, запуск панели, CSRF, write-only пароли, маскировка и
`no-store` списка, отклонение схем `proxy`, апгрейд-миграции. Перед запуском
`SHA256SUMS` должен соответствовать рабочей копии — иначе `sha256sum -c` упадёт:

```bash
shasum -a 256 S99naivepanel S99naiveproxy naivepanel.py templates/index.html > SHA256SUMS
```

Smoke-тест после каждого изменения в `naivepanel.py`:

```bash
NAIVEPROXY_DIR=./etc/naiveproxy NAIVEPROXY_INIT=./etc/init.d/S99naiveproxy \
NAIVEPROXY_LOG=./var/log/naiveproxy.log NAIVEPANEL_BIND=127.0.0.1:8089 \
./.venv/bin/python naivepanel.py &
curl -s http://127.0.0.1:8089/api/status
```

Тестовая последовательность в UI:

1. Создать пресет `home` через "+ Новый" → форма → Сохранить.
2. Нажать "→" рядом с пресетом → проверить, что в `etc/naiveproxy/config.json`
   появился тот же JSON с `chmod 0600`.
3. PUT (изменить listen port) → проверить, что `config.json` обновился.
4. Создать второй пресет `work`, активировать его, удалить `home`.
5. ⧉ на пресете → появилась копия `work-copy` с тем же паролем (проверить
   `conf.d/work-copy.json`); «пинг» в редакторе → toast с мс или ошибкой.
6. «Экспорт» → скачался JSON со всеми пресетами; удалить один пресет,
   «Импорт» → пресет вернулся, существующие не перезаписаны.
7. `/` → фокус в поиске, фильтрация списка; Ctrl+S — сохранить; Esc — закрыть
   редактор; ☀/☾ — тема переключается и переживает перезагрузку.
