# NaivePanel UI Guidelines

Дизайн-система панели: информационная архитектура, токены, иконки и правила
для новых элементов. Ограничения неизменны: один offline-HTML без CDN, без
bundl'ера и фреймворков; vanilla CSS/JS; system font stack; nonce-CSP
(никаких inline-обработчиков и внешних origin'ов).

**Структура файлов (ARCH-03):** разметка — `templates/index.html`, стили —
`panel/static/styles.css`, скрипты — `panel/static/app.js` (подключаются
версионированно, `?v=APP_VERSION`, кэш на год). Inline в HTML остался
только bootstrap темы (до первой отрисовки, под nonce). Новые стили — в
`styles.css` по токенам ниже, новый JS — в `app.js`; единственный inline-
script в HTML менять нельзя без синхронной правки CSP-теста.

## Информационная архитектура

Четыре смысловые группы (аудит UX-04). Физически UI остаётся 2–3-колоночным
дашбордом из трёх grid-карточек (desktop) — группы выражены заголовками и
якорями, а не четвёртой перестановкой DOM:

| Группа | Что входит | Где живёт |
|---|---|---|
| **Обзор** | состояние сервиса (состояние/пресет/аптайм — wide-строки, pid и соединения — пара в 2 колонки), спарклайн E2E, кнопки запуска/проверки, пресеты, фейловер | карточка `#sec-overview` (aside) |
| **Диагностика** | лог прокси/панели, фильтр ошибок, скачивание | секция `#sec-diag` внутри центральной карточки |
| **Система** | бинарник naive (проверка/обновление), версия панели и watchdog (`#sysinfo`), обновление панели, откат версий, перезапуск панели | верх карточки `#sec-system` (ops) |
| **Настройки** | смена пароля, уведомления Telegram | секция `#sec-settings` внизу ops-карточки |

Редактор пресетов — не отдельная группа: он вызывается из списка пресетов
(Обзор) и живёт в центральной карточке над Диагностикой. Основной сценарий
(выбрал пресет → правка → сохранить → активировать) на mobile не длинне­е,
чем на desktop.

### Mobile (≤800px)

- Одна колонка в порядке Обзор → Редактор/Диагностика → Система/Настройки.
- Под шапкой — sticky-навигация по четырём группам (`#secNav`, табы-якоря);
  скрывается на ≥801px. Плавный скролл — только без
  `prefers-reduced-motion`.
- Высота шапки не хардкодится: JS меряет её в `--hdr-h` (`ResizeObserver`,
  fallback `resize`); `--nav-h` — фиксированный токен 53px на ≤800px (высота
  табов), вне mobile — 0. `#secNav { top: var(--hdr-h); }` — табы стоят
  вплотную под шапкой; сумма `--hdr-h + --nav-h` используется только в
  `scroll-margin-top` якорей, чтобы заголовок не уезжал под sticky-шапку и
  табы.
- Якоря групп — `#sec-overview` и `#sec-system` (`<section>`), а
  `#sec-diag`/`#sec-settings` — это `h2`. Чтобы sticky-табы не накрывали
  заголовок, отступ задан селектору
  `section[id], h2[id^="sec-"], #editorTitle`.
- Тап-цели ≥44px, поля 16px (см. UX-02).

### Состояния редактора

Заголовок редактора несёт чип `#editorState`, различающий ровно три
состояния: **активен** (открытый пресет сейчас работает), **изменено**
(есть несохранённые правки), **сохранено** (правки записаны, пресет не
активен). Пустой чип = черновик нового пресета без правок.

Паттерны ниже — следующий релиз UI (ещё не выпущен); ограничения выше они
не меняют.

### Строка пресета

Два уровня: сверху имя и бейдж `активен`, снизу — `host:port` (перед хостом
username, а также схема, если она не `https`), справа — бейджи роли и числа
listen-адресов (`осн.`/`№N`, `×N`). Разметка: `.ptop` — имя и `активен`,
`.pmeta` — `host:port` и `.pbadges` с ролью/`×N`. Пароль и URI с кредами не
выводятся. Высота строки — не больше 72px; активный пресет всегда первый в
списке.

Действия — в меню `⋯`, а не столбиком иконок: «Сделать активным», «Добавить
в цепочку»/«Убрать из цепочки», «Дублировать», «Удалить». У активного
пресета пунктов активации и удаления нет. На экранах ≤800px у строки нет
icon-only кнопок, кроме `⋯` (44×44); базовая кнопка — 36×36 (включая
тач-планшеты шире 800px). В меню — текстовые кнопки.
`⋯` рендерится как inline-SVG (`IC.more`), поэтому правило SVG-набора выше
сохраняется.

### Действия, прерывающие сервис

Сервисные кнопки отражают состояние: «Запуск» виден только при остановленном
naive и без пресета не показывается, «Стоп»/«Рестарт» — только при
работающем. До первого ответа статуса destructive-кнопки выключены.
Кнопки «Обзора» стоят ровной сеткой (`.svcbtns`): пара «Стоп»/«Рестарт»
делит строку поровну, «Запуск» и утилиты («Скопировать PAC»,
«Проверить прокси») — во всю ширину карточки; «Проверить прокси» —
последняя строка, сразу над строкой её результата.
Той же сеткой (`.actions`: пара поровну, нечётный хвост — во всю ширину)
стоят все кнопочные группы карточек — пресеты, фейловер, редактор,
диагностика, система. Обновления бинарника и панели — одна морфящаяся
кнопка на поток: без обновнения «Проверить обновления» (.solo, во всю
ширину), при доступном обновнении — акцентная «Обновить до vX.Y.Z»
(у панели — в паре с «Что нового»); клик ветвится по состоянию
(проверить/применить), подтверждение перед применением сохраняется.
В настройках Telegram «Сохранить» и «Отключить» — пара, «Отправить
тест» — нечётный хвост. Диалоги — исключение: их кнопки справа, по
конвенции модалок; строки «поле + кнопка» остаются flex (поле тянется).

`Стоп`/`Рестарт` — подтверждение с числом текущих соединений (если счётчик
доступен). `Сохранить` активного пресета перезапускает naive: Save disabled
при отсутствии изменений, а при активном пресете и правках над кнопками
появляется предупреждение о разрыве соединений. Активация другого пресета
тоже перезапускает сервис и подтверждается, когда naive работает.

У опасных действий три веса. Сплошная заливка (`button.danger`) —
необратимое (`Удалить` пресет, `Отключить` уведомления) и полное
отключение сервиса (`Стоп`). Акцент без класса (как `Сохранить`) —
рестарт-потоки дашборда: `Рестарт`, `Перезапуск`, `Перезапустить SSH`,
`Откат версий…`.
Контурный `button.ghost.danger` (красный текст/рамка, hover —
`--err-tint`) — серьёзное, но обратимое внутри диалогов: оба `Откатить`,
`Оставить только последнюю`, `Сменить` пароль; открывашка
`Сменить пароль…` покрашена в тон своему `Сменить` — весь флоу одним
цветом. Остальной главный сценарий
(`Сделать активным`, `Обновить до`, `Запуск`) опасным цветом не
красится — красный шум обесценивает подсветку.

Удаление активного недоступно: пункт скрыт в UI, backend отвечает 409 —
defense-in-depth. Удаление пресета из цепочки отдельно предупреждает, что он
будет из неё убран.

### Диалог обновления панели

В общем `<dialog>` первым идут название операции и компактный статус; при сбое
рядом показываются понятная причина и числовой `exit_code`. Логи установщика и
панели — отдельные нативные `<details>`: лог установщика открыт во время попытки
и после ошибки, лог панели по умолчанию свёрнут. Высота логов ограничена, их
содержимое выводится только через `textContent`.

Терминальный `failed` относится к текущей попытке только при совпадении `pid` и
`state.started` с `attempt_started` из ответа apply. После сбоя ручной retry
сначала принудительно проверяет актуальный релиз, затем требует обычного
подтверждения; при ошибке проверки доступен только повтор проверки, не apply
устаревших данных. Автоматического retry нет.

Элементы, специфичные для обновления панели, скрываются и сбрасываются при
использовании того же диалога для обновления naive и отката. Mobile-правила
остаются общими: тап-цели ≥44px, управление `<summary>` с клавиатуры, возврат
фокуса и отсутствие горизонтального скролла в обеих темах.

### Вход/выход

Basic-креды после первого входа кэширует браузер — он шлёт их молча, и
«отмена» нативного промпта их не снимает. Кнопка «Выйти» (`#btnLogout`,
шапка, видна только при включённом auth) уходит на
`<scheme>//logout@<host>/`: навигация с заведомо неверной парой затирает
кэш кредов, сервер отвечает 401 и появляется нативный промпт. Серверной
части нет (fetch с фейковым `Authorization` кэш в актуальном Chromium не
меняет — проверено живым прогоном; навигация меняет). Без пароля панель
отдаёт только текст 401 — разметка UI не утекает.

### Сломанный рантайм

Панель работает кодом из памяти, но свежий интерпретатор её не поднимет
(Entware сменил Python через `opkg upgrade`). Это не offline и не ошибка
запроса: сервис жив, опасен только рестарт.

- Баннер `#rtBanner` (`role="alert"`, скрыт вне этого состояния) — обычный
  блок **над сеткой карточек**, первым на странице; не fixed и не внутри
  `<main>` (он не grid-элемент), боковые отступы повторяет у `main`. Вес —
  предупреждение: рамка `--warn`, без сплошного красного (красный — только у
  необратимого). Заголовок «Панель не запустится после перезапуска», причина,
  деталь моноширинным, рецепт для SSH в `<code>` (переносится
  `overflow-wrap:anywhere`), затем подсказка, что прокси работает как прежде.
- Кнопки — парной сеткой `.rt-actions`: «Исправить и перезапустить» —
  акцентная (рестарт-поток), «Перепроверить» — ghost; на ≤800px в столбик.
- Причина, деталь и рецепт приходят с сервера (там пути) — только
  `textContent`.
- «Перезапуск» и «Откатить» не выключаются заранее: клик — это синхронная
  перепроверка на сервере, а вердикт мог устареть (зависимости починили по
  SSH). `409` показывается тостом с рецептом.
- Ремонт идёт в общем диалоге обновления (`#updDlg`): заголовок
  «Восстановление зависимостей», успех — «Зависимости восстановлены —
  перезагружаю страницу…»; кнопка повтора обновления скрыта (другой поток).
  Успех определяется по `panel.started` (другой процесс), а не по версии —
  при ремонте она не меняется.
- Первое появление баннера — без тоста (он и так первый на странице);
  тост сопровождает только переходы: «сломано → ok» и обратный.

### Offline

Два сетевых полла подряд не прошли (или упал начальный `refreshAll`) —
показываем фиксированный баннер «Нет связи с панелью» с временем последнего
успешного обновления и кнопкой «Повторить». Обрывом считаются сетевые ошибки
и 502/503/504; 401/500 — нет, панель ответила. Шапка в это время показывает
«нет связи», а не «работает»; сервисные кнопки выключены, последние данные
остаются на экране. Первый успешный ответ убирает баннер и сообщает о
восстановлении.

Первый запуск при недоступной панели — error-state с «Повторить» в списке
пресетов, а не вечный skeleton.

### Первый запуск

Пустой список — центрированный empty-state («Пресетов пока нет») с CTA
«Вставить ссылку»; редактор не рендерится. Если пресеты есть, но редактор
закрыт — одна компактная строка «Пресет не выбран» с кнопкой «Создать
пресет», без пустого заголовка и полей. Фейловер скрыт при <2 пресетах,
экспорт — при 0; «Запуск» и «Проверить прокси» недоступны без пресета.

## Дизайн-токены

Токены объявлены в `:root` (тёмная — базовая, светлая переопределяет).
Новые правила используют токены; существующие переводятся на них по мере
правки (революционный рефакторинг всех правил не делается).

| Семейство | Токены |
|---|---|
| Отступы | `--sp-1` 4px · `--sp-2` 8px · `--sp-3` 12px · `--sp-4` 16px · `--sp-5` 20px · `--sp-6` 24px |
| Шрифты | `--fs-11` … `--fs-16` (11/12/13/14/16px); моно — `--font-mono` |
| Радиусы | `--r-s` 8px (кнопки/поля) · `--r-m` 10px (строки/тосты) · `--r-l` 12px (карточки/диалоги) |
| Тени | `--shadow-1`, `--shadow-2` (тематические, уже были) |
| Z-index | `--z-header: 5` · `--z-nav: 6` · `--z-banner: 9` · `--z-toast: 10` |
| Высоты | `--hdr-h` (измеренная шапка) · `--nav-h` (фикс. 53px на ≤800px, вне mobile — 0) · `--conn-banner-h` (измеренный offline-баннер) |
| Фокус | `--focus-ring: 2px solid var(--acc)` (offset 1px) — единый для всего интерактивного |
| Статусы | `--status-ok: var(--acc)` · `--status-err: var(--err)` · `--status-warn: var(--warn)` |

## Иконки

Единый набор inline-SVG (16×16 viewBox, `stroke="currentColor"`,
`fill="none"`, класс `ic`, `aria-hidden="true"` — доступное имя даёт контрол
вокруг; толщина линии 2, у точек меню — 2.4, у контурных empty-state — 1.6).
Заменяют разнородные Unicode-глифы
(UX-06): ☀/☾, ✕, →, ⧉, ↑, ↓, ⛓. Смешивать глифы и SVG в новых элементах
нельзя; текстовые кнопки («Сохранить», «Проверить») иконок не получают.
`⋯` в разделах выше — это кнопка меню (`IC.more`, три точки inline-SVG), а
не Unicode-глиф; «Дублировать» больше не рисуется как `⧉`.

## Правила для изменений

1. Сначала группировка/заголовки, потом навигация, потом подача редактора;
   JS-логику не переписывать одновременно с перемещением DOM.
2. После каждого шага: полный pytest-suite + live-скриншоты
   375/390/768/1024/1440 в обеих темах; горизонтальный скролл на 375 = баг,
   строка пресета ≤72px, nav не перекрывает шапку.
3. Контраст текста — WCAG AA (4.5:1); в pytest есть контракт-тест,
   считающий контраст по токену `--acc`.
4. Диалоги — только нативные `<dialog>`; фокус после закрытия возвращается
   на триггер.
