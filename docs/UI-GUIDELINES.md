# NaivePanel UI Guidelines

Дизайн-система панели: информационная архитектура, токены, иконки и правила
для новых элементов. Ограничения неизменны: один offline-HTML без CDN, без
bundl'ера и фреймворков; vanilla CSS/JS; system font stack; nonce-CSP
(никаких inline-обработчиков и внешних origin'ов).

## Информационная архитектура

Четыре смысловые группы (аудит UX-04). Физически UI остаётся 2–3-колоночным
дашбордом из трёх grid-карточек (desktop) — группы выражены заголовками и
якорями, а не четвёртой перестановкой DOM:

| Группа | Что входит | Где живёт |
|---|---|---|
| **Обзор** | состояние сервиса, спарклайн E2E, кнопки запуска/проверки, пресеты, фейловер | карточка `#sec-overview` (aside) |
| **Диагностика** | лог прокси/панели, фильтр ошибок, скачивание | секция `#sec-diag` внутри центральной карточки |
| **Система** | бинарник naive (проверка/обновление), обновление панели, откат версий, перезапуск панели | верх карточки `#sec-system` (ops) |
| **Настройки** | смена пароля, уведомления Telegram | секция `#sec-settings` внизу ops-карточки |

Редактор пресетов — не отдельная группа: он вызывается из списка пресетов
(Обзор) и живёт в центральной карточке над Диагностикой. Основной сценарий
(выбрал пресет → правка → сохранить → активировать) на mobile не длинне­е,
чем на desktop.

### Mobile (≤800px)

- Одна колонка в порядке Обзор → Редактор/Диагностика → Система/Настройки.
- Под шапкой — sticky-навигация по четырём группам (`#secNav`, табы-якоря);
  скрывается на ≥801px. Плавный скролл — только без
  `prefers-reduced-motion`.
- Тап-цели ≥44px, поля 16px (см. UX-02).

### Состояния редактора

Заголовок редактора несёт чип `#editorState`, различающий ровно три
состояния: **активен** (открытый пресет сейчас работает), **изменено**
(есть несохранённые правки), **сохранено** (правки записаны, пресет не
активен). Пустой чип = черновик нового пресета без правок.

## Дизайн-токены

Токены объявлены в `:root` (тёмная — базовая, светлая переопределяет).
Новые правила используют токены; существующие переводятся на них по мере
правки (революционный рефакторинг всех правил не делается).

| Семейство | Токены |
|---|---|
| Отступы | `--sp-1` 4px · `--sp-2` 8px · `--sp-3` 12px · `--sp-4` 16px · `--sp-5` 20px · `--sp-6` 24px |
| Шрифты | `--fs-11` … `--fs-16` (11/12/13/14/16px); моно — `--font-mono` |
| Радиусы | `--r-s` 8px (кнопки/поля) · `--r-m` 10px (строки/тосты) · `--r-l` 12px (карточки/диалоги) |
| Тени | `--shadow-1`, `--shadow-2` (тематические, уже были) |
| Z-index | `--z-header: 5` · `--z-nav: 6` · `--z-toast: 10` |
| Фокус | `--focus-ring: 2px solid var(--acc)` (offset 1px) — единый для всего интерактивного |
| Статусы | `--status-ok: var(--acc)` · `--status-err: var(--err)` · `--status-warn: var(--warn)` |

## Иконки

Единый набор inline-SVG (16×16 viewBox, `stroke="currentColor"`,
`stroke-width="2"`, `fill="none"`, класс `ic`, `aria-hidden="true"` —
доступное имя даёт контрол вокруг). Заменяют разнородные Unicode-глифы
(UX-06): ☀/☾, ✕, →, ⧉, ↑, ↓, ⛓. Смешивать глифы и SVG в новых элементах
нельзя; текстовые кнопки («Сохранить», «Проверить») иконок не получают.

## Правила для изменений

1. Сначала группировка/заголовки, потом навигация, потом подача редактора;
   JS-логику не переписывать одновременно с перемещением DOM.
2. После каждого шага: полный pytest-suite + live-скриншоты
   375/768/1024/1440 в обеих темах; горизонтальный скролл на 375 = баг.
3. Контраст текста — WCAG AA (4.5:1); в pytest есть контракт-тест,
   считающий контраст по токену `--acc`.
4. Диалоги — только нативные `<dialog>`; фокус после закрытия возвращается
   на триггер.
