# Roadmap NaivePanel

Анализ пробелов функциональности (октябрь 2026, после v0.11.1). Статусы:
**готово** / **в работе** / **запланировано** / **осознанно не делаем**.

Приоритет — комбинация ценности для сценария «роутер держит прокси всего дома»
и стоимости реализации. Пункты внутри разделов отсортированы по приоритету.

> Комплексный план устранения находок аудита архитектуры, безопасности и UI/UX
> с TDD-задачами и критериями приёмки:
> [2026-11-05 Architecture, Security and UX Improvement Plan](plans/2026-11-05-architecture-security-ux-improvement-plan.md).

## 1. Надёжность

| # | Фича | Приоритет | Статус | Заметки по дизайну |
|---|------|-----------|--------|--------------------|
| 1.1 | **Watchdog для naive** — авто-рестарт упавшего процесса | P0 | реализовано (v0.12) | Поток в панели, отслеживает переход running→down; deliberate stop (init-скрипт пишет stop-маркер) не трогаем; защита от флаппинга (лимит рестартов); `NAIVEPANEL_WATCHDOG=0` в panel.conf отключает. Минус подхода: панель сама лежит → watchdog не работает (cron-фолбэк — возможное улучшение) |
| 1.2 | **E2E-проверка «прокси реально проксирует»** | P0 | реализовано (v0.12) | `POST /api/e2e` + кнопка «Проверить прокси»: HTTP CONNECT / SOCKS5-туннель через listen активного пресета до echo-хоста (`NAIVEPANEL_E2E_URL`) + exit-IP. Отличает «TCP до upstream есть» (`/api/probe`) от «прокси работает целиком»: аутентификация, форвардинг, remote-DNS. Поверх этого строится 1.3 |
| 1.3 | **Автофейловер пресетов** — цепочка «основной → запасной» upstream | P1 | реализовано (v0.12) | `failover.json` + подсекция «Фейловер» в карточке «Пресеты» (с v0.17) + `GET/PUT/DELETE /api/failover`. Монитор делает E2E-проверку активного пресета раз в `NAIVEPANEL_FAILOVER_INTERVAL` (30с); `NAIVEPANEL_FAILOVER_THRESHOLD` (3) неудач подряд — переключение на следующий пресет тем же кодом, что ручной activate. Гистерезис есть; авто-возврата в v0.12 не было (возврат ручной) — добавлен в 1.3a (v0.14). Успех = полный HTTP-ответ echo-хоста (честный критерий с v0.13): ACK туннеля без данных — неудача. С v0.17 — единое управление в списке пресетов: бейджи/тумблер/«Порядок», немедленный PUT; цепочка в export/import |
| 1.4 | **Rollback обновлений** панели и бинарника naive | P1 | реализовано (v0.15) | Бэкапы уже делались self-update'ом (панель: `backup/vX.Y.Z/`, бинарник: `naive.previous`) — закрыта недостающая половина: `GET/POST /api/rollback`, `DELETE /api/rollback/<v>`, `POST /api/rollback/cleanup {keep:N}` + диалог «Откат версий…» в UI. Откат панели обратим (текущие файлы тоже снапшотятся), бинарник проверяется `--version` до возврата, тег прежней версии пишется в `naive.previous.tag`. Гейт и 409 — как у обновлений |
| 1.3a | **Авто-возврат на основной** (opt-in чекбокс в цепочке) | P1 | реализовано (v0.14) | TCP-гистерезис N=3 (`NAIVEPANEL_FAILOVER_RETURN_ALIVE`) → проба живым naive из CLI (без временных файлов, идея Lex) с полным E2E → активация. Неудачная проба → cooldown 900с. Работает только при стабильном текущем. UI: чекбокс + «ждём возврата: X n/N» + «возвратов: N». Каскад при нескольких запасных — тоже с пробой: переключаем на первого живого |
| 1.5 | **Уведомления** (Telegram-бот / webhook) | P2 | реализовано (v0.14) | Очередь + sender-поток, отправка curl'ом (единый путь наружу). Каналы: Telegram (`NAIVEPANEL_TG_TOKEN`+`NAIVEPANEL_TG_CHAT`) или webhook (`NAIVEPANEL_NOTIFY_URL`, POST JSON). Секреты только в panel.conf; UI — статус канала, с v0.16 — настройка Telegram (токен write-only) и тест. События: switch/return/return-probe-failed/exhausted/watchdog-restart/tripped. Дедуп 1/мин; прямая отправка с роутера (лежащий прокси не мешает). UI-настройка Telegram в v0.16 (токен write-only, живое применение, тест) |

## 2. Наблюдаемость

| # | Фича | Приоритет | Статус | Заметки |
|---|------|-----------|--------|---------|
| 2.1 | **История E2E-проверок** — последние N результатов с таймингами, спарклайн в статус-карте | P1 | реализовано (v0.13) | Монитор (бывший failover-поток) проверяет активный пресет всегда, не только при фейловере; каждая проверка — в кольцевой буфер `e2e-history.jsonl` (`NAIVEPANEL_E2E_KEEP`, сутки по умолчанию). Спарклайн-полоска в статус-карте + `GET /api/e2e/history?last=N` со статистикой (availability, avg_ms, окно). `NAIVEPANEL_FAILOVER=0` отключает монитор целиком |
| 2.2 | **Счётчик активных соединений** через прокси | P2 | реализовано (v0.22.1) | Из `/proc/net/tcp{,6}`, без `ss`/`netstat` (на OpenWrt их нет): ESTABLISHED на всех listen-портах активного пресета, **включая loopback** — иначе клиенты за локальным форвардером (xray) теряются. В API `clients` — только уникальные прямые не-loopback адреса; в UI одна строка «соединений». Дизайн: [2026-11-07](plans/2026-11-07-active-connections-design.md) |
| 2.3 | **Статистика аптайма** — % за день/неделю, время с последнего рестарта | P3 | реализовано (v0.23) | Журнал ПЕРЕХОДОВ процесса up/down `uptime-history.jsonl` (30 дней, переживает рестарт панели), пишет монитор-поток в начале каждого цикла — до idle-веток: осознанный stop = честный downtime. Агрегация на лету в `/api/status` (`uptime_stats.day/week` = pct + observed_s, `restarts_day`); «время с последнего рестарта» — уже существующая строка uptime. Знаменатель — наблюдённый отрезок (мин(окно, первая запись)), свежая установка не показывает «неделю нулей»; неизменное состояние при рестарте панели не рождает ложный переход (якорь по последней записи). «Время с последнего рестарта» = строка uptime |
| 2.4 | Графики трафика (bytes in/out) | P3 | запланировано | Сложно без поддержки со стороны naive; скорее всего через 2.2-подобные снапшоты или парсер лога. Низкий приоритет |

| # | Фича | Приоритет | Статус | Заметки |
|---|------|-----------|--------|---------|
| 3.1 | **PAC-файл** — `/proxy.pac` из панели + кнопка «скопировать адрес прокси» для устройств LAN | P2 | реализовано (v0.23) | PAC из listen активного пресета (`SOCKS5`/`PROXY`); `0.0.0.0`/`::` заменяются хостом из запроса — устройство достигает прокси по адресу, по которому получило PAC; не-loopback listen раньше loopback; `?direct=1` добавляет DIRECT; без активного пресета — честный DIRECT. | 3.2 | **Импорт пресета одной строкой** — вставил `https://user:pass@host:port` → готовый пресет | P2 | реализовано (v0.23) | Поле «Строка подключения» над списком пресетов → `POST /api/configs/parse` (серверный парсер — креды до последнего `@`, percent-декодирование) → редактор заполнен: имя-подсказка из хоста (занятое → `-2`), upstream, username, пароль. http/quic не раскладываются (пересборка из полей даёт только https) — остаются в upstream целиком |
| 3.3 | **Смена пароля админа из UI** — генерация bcrypt в панели с проверкой старого пароля | P2 | реализовано (v0.16) | `POST /api/password` + диалог «Сменить пароль…»: текущий пароль сверяется bcrypt'ом, новый — 8–72 байта (UTF-8). `admin.pass` пишется атомарно (tmp + rename, 0600), кэш auth сбрасывается — следующий запрос уже с новыми кредами. Без `admin.pass` (auth выключена) — 409, кнопка в UI скрыта |
| 3.4 | Автобэкап пресетов при изменении (с retention) | P3 | запланировано | Сейчас export только ручной. Снапшот conf.d перед каждым activate/PUT + последние N копий |
| 3.5 | Теги/ручной порядок пресетов | P3 | запланировано | Косметика |

## 5. Осознанно не делаем

Обоснования, чтобы не возвращаться к обсуждению без новых вводных.

- **Multi-user / RBAC** — один админ на роутер; роли read-only vs admin не оправдывают усложнение auth.
- **HTTPS termination в панели** — решается внешним reverse proxy (задокументировано); добавлять TLS-стек в single-file панель на роутере не хотим.
- **Управление upstream-серверами** (Caddy/forwardproxy) — другой продукт; панель — клиент.
- **Полный мониторинг-стек (Prometheus и т.п.)** — overkill для роутера; закрывается разделом 2.
